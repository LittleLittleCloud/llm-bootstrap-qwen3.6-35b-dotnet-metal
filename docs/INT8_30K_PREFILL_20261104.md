# INT8 KV: 30K prefill tuning

The new `attention_online_int8_q32_k256_r2` reduces native 29,939-token prefill
latency by approximately 4% versus the previous INT8 kernel and 3% versus the
FP16 control. This is a local native diagnostic, not a full endpoint evaluation
or a new Splash comparison. INT8 remains opt-in.

## Change

The query tile remains 32 grouped rows, with eight SIMD groups and eight query
heads per KV head. The key tile grows from 128 to 256. Each lane loads its K/V
scales once per key tile and reuses them across four query rows. QK uses
TensorOps multiply mode to initialize its destination, removing explicit score
zeroing. FP16 queries, INT8 codes, BF16 scaled probabilities, FP32 accumulation,
cache format and quantization remain unchanged. No dispatch or scratch buffer
is added. Explicit `--tile 32,128` retains the old diagnostic control.

Screening included alternative softmax subgroup widths, vectorization, Q64,
query staging, additional prefetch and unrolling. None justified replacing the
simple selected combination. These microbenchmarks do not isolate the individual
contribution of every change in the selected combination.

## Matched native controls

M5 Pro, 20 GPU cores, 48 GiB, macOS 26.6.2. Base commit `41f8e47` plus the
worktree implementation. All runs use the same pinned target, affine-8 group-64
weights, BF16 expert outputs, DFlash2 draft, FP16 draft KV, staged8 DeltaNet,
dispatch fusion 29, 2048-token chunks and context window 32768.

Serial process order: old INT8, new INT8, old INT8, FP16. Each process runs one
first-use request, five warm requests with prefix reuse cleared, then a separate
counter request. Loading/tokenization are excluded; first-token computation,
draft setup and prefix snapshot creation are included. Each process runs from
its immutable binary directory, ensuring it loads that directory's Metal source.

| Variant | Warm median, ms | Tokens/s | Dispatches |
| --- | ---: | ---: | ---: |
| Old INT8 before | 13,165.704 | 2,274.01 | 16,324 |
| New INT8 | 12,642.211 | 2,368.18 | 16,324 |
| Old INT8 after | 13,177.791 | 2,271.93 | 16,324 |
| FP16 reference | 13,026.578 | 2,298.30 | 16,344 |

New INT8 latency falls 3.98%/4.06% against the bracketing old INT8 controls,
and 2.95% against FP16. All warm windows have zero new whole-machine swap-outs
and no thermal warnings. Whole-process swap-outs, including load, are 44.875 MiB
for old-before, zero for new and old-after, and 176.625 MiB for FP16. Existing
swap and some swap-ins remain; this is not a memory-pressure-free experiment.

Attention/preparation counter intervals fall from 3931/3936 ms to 3371 ms.
Counter wall overhead is 7.70%, 4.83%, 6.78% and 16.24%, respectively; intervals
may overlap and are not additive wall costs. Speed claims above use uninstrumented
warm requests, not the counter totals.

An independent 15-sample alternating probe of the actual production helper uses
non-unit scales and the same queries/cache for both variants:

| History / query rows | Old K128 GPU median, ms | New K256 GPU median, ms |
| --- | ---: | ---: |
| 0 / 33 | 0.02154 | 0.02408 |
| 8192 / 2048 | 17.22825 | 14.82842 |
| 27900 / 2048 | 50.38579 | 44.22633 |

The tiny case regresses by about 2.5 microseconds. This tuning targets long
prefill; it does not establish a benefit at every length.

## Numerical validation

All eight kernel cases pass CPU quantization/FP64 attention checks, cache
prefix/tail guards, alias checks, fused/separate preparation, scalar verification
and the tiny-V range check. Maximum arithmetic error versus attention on the
already-quantized cache is 0.00115145; maximum quantization error versus FP16 is
0.00664643. These are separate error sources. All eight cases also pass Metal
shader validation. The three independent production-helper probes pass their
CPU reference checks, with maximum absolute error 0.00012659.

Seven real-model fixtures in serial and speculative modes produce 14 old/new
comparisons, with 28 passing answers and identical generated token sequences.
First-token top-1 matches throughout. Maximum softmax KL is 4.9274e-5 nats;
maximum total variation is 0.00031969. Centered logit relative L2 reaches 14.55%:
raw logits are not numerically identical. This small set of high-confidence
tasks, including 10K/30K retrieval and prefix reuse, does not replace broad
quality evaluation. Earlier cache-state regressions are recorded in the initial
INT8 report; they were not rerun as part of this kernel-only tuning.
